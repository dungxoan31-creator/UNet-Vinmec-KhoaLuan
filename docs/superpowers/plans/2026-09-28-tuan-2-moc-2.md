# Tuần 2 Mốc 2: Chốt mô hình bằng Validation và hoàn thiện HITL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Đến 05/10/2026, chốt mô hình segmentation bằng Train/Validation, hoàn thiện luồng Upload → Segmentation → Original/Mask/Overlay → Review/Edit → Confirm và chuẩn bị đánh giá Test Set cho Mốc 3.

**Architecture:** Giữ FastAPI và frontend JavaScript/Canvas hiện có. So sánh các checkpoint trên Validation với cùng pipeline, chốt cấu hình rồi khóa manifest Test Set; không chạy suy luận, xem mask hay tính metric trên Test trong Mốc 2. API chỉ phục vụ checkpoint đã kiểm chứng; mặt nạ bác sĩ xác nhận đi qua RLE 512×512 và được lưu cùng dấu vết duyệt.

**Tech Stack:** Python 3.12, PyTorch, OpenCV, Pandas, FastAPI, SQLAlchemy, pytest; HTML/CSS/JavaScript Canvas hiện có.

**Spec:** `docs/superpowers/specs/2026-09-28-moc-2-gvhd-requirements.md` (phản hồi GVHD do người dùng cung cấp), `docs/reports/Bao_Cao_Tien_Do_Moc_1_NguyenHuuDung.md`, `AGENTS.md`, `TECH_STACK.md`.

## Global Constraints

- Patient-level split giữ nguyên `ai_training/splits/{train,val,test}.csv`; chỉ kiểm tra manifest và trùng Patient ID để niêm phong Test. Không đọc ảnh/mask, chạy mô hình, tính metric hoặc chọn threshold trên Test trong Mốc 2.
- Ảnh/mask dùng letterbox `512×512`, mask dùng nearest-neighbor; huấn luyện dùng Dice + BCE như baseline hiện hành.
- AI chỉ đưa ra gợi ý; chỉ bản bác sĩ thực sự xác nhận mới mang trạng thái đã duyệt. Không dùng mặc định tên bác sĩ hay số liệu lâm sàng giả làm dữ liệu thật.
- Báo cáo riêng metric phân đoạn trên ca có lesion và trên Empty Mask; không gộp Dice/IoU trung bình qua hai nhóm. Không diễn giải Dice, IoU, Recall, Precision, Specificity thành độ chính xác chẩn đoán.
- Chỉ nhận định loại tổn thương khi có metadata hoặc bác sĩ xác nhận; không suy diễn “bất thường” thành “ác tính”.
- So sánh dưới cùng preprocessing, tập Validation và cách tổng hợp; threshold/loss/hyperparameter chỉ chọn từ Train/Validation. Báo cáo checksum checkpoint và số ca Validation thực sự đánh giá.
- Diễn đạt đúng: “loại bỏ việc trùng bệnh nhân giữa các tập và giảm nguy cơ data leakage”; không tuyên bố loại bỏ 100% mọi nguy cơ rò rỉ.
- Thời gian API mục tiêu theo báo cáo Mốc 1: dưới 500 ms/ảnh trên GPU cá nhân; nếu không đạt, báo cáo số đo và điều kiện đo thực tế, không tuyên bố đạt.
- Không đưa dữ liệu bệnh nhân hoặc checkpoint lớn vào Git nếu chưa có cơ chế phân phối được phép.

## Review Focus

1. Test Set bị đọc hoặc dùng trong tinh chỉnh: kiểm tra ranh giới truy cập, chỉ cho phép xác minh manifest/hash, không suy luận hay xem nhãn — Tasks 1–2.
2. Checkpoint sai kiến trúc: từ chối nạp và báo lỗi, không tự đổi sang mô hình khác — Task 2.
3. Ảnh không hợp lệ hoặc chưa có trọng số: API trả lỗi có ý nghĩa và không ghi prediction — Task 3.
4. RLE sai kích thước/tổng run hoặc ca không có prediction: từ chối duyệt, không đánh dấu Ground Truth — Task 4.
5. Mask sau khi sửa, zoom/pan hoặc reset: bản lưu phải khớp pixel Canvas và trạng thái thao tác — Task 5.
